# MemorySync v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 构建一个跨主机、跨 Claude Code/Codex 的团队项目记忆库：Git 作事实来源，`memsync` CLI 负责同步、渲染、写回、治理与维护。

**Architecture:** 单仓库 TypeScript CLI，所有记忆读写都在 CLI 内；启动时由 Claude Code / Codex 的 hooks（或 Codex 的 AGENTS.md + wrapper 降级）调用 CLI，拉取团队 Git 记忆仓库并注入有预算的上下文包；会话结束自动提交并推送追加式日志。

**Tech Stack:** TypeScript、Node.js ≥22（开发机 24）、commander、yaml、vitest、esbuild、系统 Git（`child_process.execFile`）。

**Spec:** `docs/superpowers/specs/2026-11-13-shared-team-memory-design.md`

## Global Constraints

- Node.js ≥ 22；TypeScript `strict`；ESM（`"type": "module"`）。
- 默认 `MEMSYNC_HOME=~/.memsync`；仓库在 `$MEMSYNC_HOME/repo`。
- 不引入数据库、HTTP 服务、MCP SDK、向量库、LLM API。
- Windows 优先；所有文件 UTF-8；记忆仓库 `.gitattributes` 强制 LF。
- 启动上下文默认 12,000 字符，硬上限 24,000 字符。
- 单条 note 上限 8,192 字节；每 5 条 note checkpoint 一次。
- `recall` 默认 5 条命中、每条 ≤800 字符、总量 ≤4,000 字符。
- 维护策略默认：主线有新提交、距上次成功 ≥72 小时、失败冷却 6 小时。
- 拉取超时 5 秒；hook 超时 30 秒；Codex app-server 探测超时 10 秒。
- 会话日志文件名：`HHMMSS_<userSlug>_<hostSlug>_<tool>_<sessionShort>.md`。
- 不保存对话原文；不写入密钥；所有诊断只记录哈希与计数。
- 记忆仓库默认分支允许团队成员直接 push，不强制 MR。

## Review Focus

1. **两名用户同一分钟写回并推送**：不得需要人工解决冲突；双方记录都要在拉取后完整出现。测试放在 Task 2/14。
2. **离线或拉取失败时启动**：必须注入缓存包并标注过期，不阻塞工具。测试放在 Task 6/14。
3. **AI 不写 summary / 会话崩溃**：结束时仍要落下可用的统计与 `derived` 摘要。测试放在 Task 5/14。
4. **笔记包含密钥形态（`sk-...`）**：必须拒绝写入且不落盘。测试放在 Task 4/14。
5. **Codex hook 未信任或升级后 hash 变化**：不得执行旧 hook；必须要求重新确认或降级。测试放在 Task 11/14。

- [ ] **Step 3: 实现**

- `runGit` 使用 `execFile("git", args, { cwd, timeout, windowsHide: true })`；超时/非零码不抛，交给调用方判断；`gitOrThrow` 对非零码抛带 stderr 的错误。
- `withLock` 用 `fs.open(lockPath, "wx")`；锁内写 `{ pid, startedAt }`；忙时 50ms 重试；`mtime` 超过 `staleMs`（默认 30s）则删除重试；`finally` 删除锁。
- `cloneOrUpdateRepo`：目录不存在则 `git clone <remoteUrl> <repoPath>`；存在则 `pullRebase`。
- `pullRebase`：`git pull --rebase --autostash`，5s 超时；非零码包含 `CONFLICT` → `conflict`，`ETIMEDOUT` → `timeout`，其余 `error`。
- `commitPaths`：`git add -- <paths>`，有变更才 `git commit -m <message>`，返回短 SHA。
- `pushWithRetry`：`git push`；失败时 `pullRebase` 后重试，最多 3 次；仍失败返回原因。
- `hasPendingPush`：`git rev-list --count @{u}..HEAD`（无 upstream 用 `origin/<branch>`）> 0。

- [ ] **Step 4: 实现 `init` 命令**

`memsync init --remote <url> [--name <name>] [--email <email>]`：

1. 读取全局配置；缺 email 时从 `git config user.name/user.email` 推导，仍缺失则报错；
2. `cloneOrUpdateRepo` 到 `$MEMSYNC_HOME/repo`；
3. 写入 `$MEMSYNC_HOME/config.json`；
4. 在仓库内 `git config core.autocrlf false`，并确保 `.gitattributes` 含 `* text=auto eol=lf`；
5. 输出 repoPath、identity、remote。
